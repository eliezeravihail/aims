# §7 validation — does "a stated capability is never a YAGNI cut" stop the subtractive over-cut?

The plant→mineral loss (`../plant-mineral-id/`) was an aims **builder** miss: its self-review **cut** a
range-valued observation as YAGNI, though the card and X4 named it — a stated present force. The candidate
§7 wording ("a capability named by an R/X/C item is a present force by definition, never a YAGNI cut") must
prove itself on a **product it has not seen** before entering `design-principles.md`, not be self-confirmed
on the round that produced it (the discipline Pavel named).

## Design (an internal A/B on the wording — n = 2 per PROTOCOL for a load-bearing skill change)
- Fresh, unrelated product: an **alerting rule engine** (`card.md`) whose stated X-items include a **band
  threshold** and a **ranged event value** — a range/overlap capability a single-scalar model cannot
  represent, and which a subtractive pass is tempted to cut. Frozen Step-0 inventory in `inventory.md`.
- Two aims arms, **identical in every way except one clause** in their `design-principles.md`:
  - **fixed** — with the §7 R/X/C-is-a-present-force clause.
  - **unfixed** — current shipped wording (what the plant→mineral builder used).
- Reading: does each arm's **type model represent the ranged/band cases** (C2–C4 in the inventory), or does
  the subtractive pass collapse them to a point (the plant→mineral §1 S4)? Blind of method identity; the
  measure is a §1 correctness fact (representable or not), not a taste call.

`results.md` records the outcome. The clause is folded into `design-principles.md` **only if** the fixed arm
keeps the capability where the unfixed arm cuts it.
