05 · Use it

Install & run

aims is a Claude Code plugin. Requirements: Python 3 (standard library only) and bash — nothing else.

Setup

Two steps

1 · Install the plugin

/plugin marketplace add eliezeravihail/aims
/plugin install aims@aims

From within Claude Code. Makes the aims-guide skill and the /aims-* commands available in every session — including /aims-sharpen-prompt, which is useful on its own and needs no project setup.

2 · Set up a project

/install-on .

In the project you want to use aims on. Idempotent. Installs the two per-project hooks (session-start, and the read-time staleness advisory) plus the anchor tool under .aims/, and wires them into .claude/settings.json. It never touches your code or existing records.

Drive the design

The commands

  • auto/aims-plan-and-build "<task>" — the full autonomous loop: discovery → design objective → build → review → file the records, pausing only for open product decisions.
  • plan/aims-plan "<task>" — choose one design objective, file the durable records it commits to, draft the Worker handoff; stop for review with a plan report.
  • panel/aims-panel-plan — the opening-round variant: set one objective, fan the design across three axis-focused Workers, and compose the best of each with a merge agent.
  • adapt/aims-add-feature "<change>" — plan a change to code that already exists — a pure refactor, or an adaptation that absorbs a new requirement. Learns the code and characterizes its behavior first (not the greenfield flow), then picks one add-feature objective against add-feature-principles; stop for review.
  • build/aims-build — delegate the objective to a Worker (or run it inline); stop before evaluation.
  • review/aims-review <branch | diff | path> — measure the result against the exit criteria with the review panel; also works standalone on any diff, branch, or PR.
  • solo/aims-sharpen-prompt — the framing discipline on its own: turn a vague ask into a real brief before executing. No project setup, not limited to software.
  • setup/install-on <path> — install aims' per-project pieces (the two hooks + the anchor tool) into a target project.
As it works

Knowledge accrues beside the code

Records are filed next to the code — a <file>.md companion per source file, plus root records — so a later session continues by navigating to them. See In practice.
